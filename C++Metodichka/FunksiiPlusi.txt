Нельзя создавать одну функцию внутри другой.
Нельзя вызвать функцию до ее объявления.

Массивы можно передавать внутрь функции в качестве
аргументов. Важным отличием от обычных переменных,
является то, что все изменения, происходящие с массивом внутри функции — сохраняются при выходе из неё.
Для передачи одномерного массива достаточно просто
указать пустые квадратные скобки.

Если в функцию передаётся двумерный массив, то описание соответствующего аргумента функции должно
содержать количество столбцов; количество строк —
несущественно.


В C++ нельзя создать функцию, которая принимает двумерный массив без явного указания хотя бы одного размера массива. Это связано с тем, что при передаче массива в функцию без указания его размера в качестве параметра компилятор не знает, как правильно интерпретировать этот массив.

Тем не менее, есть способы обойти это ограничение. Например, можно передать дополнительный параметр, указывающий количество строк, и затем внутри функции использовать другой способ определения второго размера массива. Одним из распространенных методов является использование стандартной библиотечной функции sizeof, которая возвращает размер объекта в байтах.

Прототипы функций или второй способ объявления
При втором способе объявления функции необходимо
сообщить компилятору о том, что функция существует. Для
этого до main предоставляется имя функции, ее аргументы,
а также тип возвращаемого значения. Такую конструкцию называют прототипом функции. Когда компилятор
встречает прототип функции он точно знает о том, что
функция существует в программе после main — и, она
должна там быть.

#include<iostream>
using namespace std;

void Funk1();
int Funk2(int a);

int main() {
	Funk1();
	cout << Funk2(2) + 2;
	return 0;
}

void Funk1() {
	cout << "Provet";
}

int Funk2(int a) {
	return a + 1;
}

Область видимости
Любые фигурные скобки в программном коде образуют, так называемую область видимости, это означает,
что переменные, объявленные внутри этих скобок будут
видны только внутри этих скобок. Другими словами, если
к переменной, созданной внутри функции, цикла, if и так
далее обратится из другого места программы, то произойдет ошибка, так как после выхода из фигурных скобок
эта переменная будет уничтожена.

int a=5;
if(a==5){
 int b=3;
}
// ошибка! b не существует
// она существовала только внутри if
cout<<b;

Согласно правилам области видимости — переменные
делятся на два вида — локальные и глобальные.
Локальные переменные создаются внутри какого —
нибудь отрезка кода, что это значит для программы, мы
уже знаем.

Глобальные переменные создаются вне всяких областей
видимости. Преимущественно до функции main(). Такая
переменная видна в любом месте программы. По умолчанию глобальные переменные в отличии от локальных
инициализируются 0. И, главное, те изменения, которые
происходят с глобальной переменной внутри функции,
при выходе из последней сохраняются.
Примечание: Запомните — если есть, например,
глобальная переменная под названием а, а внутри
функции определяется переменная под тем же
именем, то тогда внутри функции будет использоваться переменная, объявленная внутри этой
функции. Поэтому избегайте применения имен
переменных, которые незримо уже используются
во внешних областях видимости. Этого можно
достигнуть, вообще избегая использования в программе одинаковых идентификаторов.

int a=23; // глобальная a
int main(){
 int a=7; // локальная a
 cout<<a; // 7, используется локальная
 return 0;
}

Каждый раз, когда функция SomeFunc будет доходить
до места объявления переменной a, она будет создаваться и инициализироваться 0. При завершении работы
функции переменная будет уничтожаться. В нашем случае переменная создавалась и уничтожалась три раза.
А что, если нам нужно сделать так, чтобы переменная
a не уничтожалась при выходе из функции и сохраняла
своё значение между вызовами?
Для решения этой задачи нам нужно использовать
статическую локальную переменную. Этот вид локальных переменных не уничтожается при выходе за пределы
области видимости. Такие переменные создаются один раз
при первом обращении и уничтожаются, когда программа
заканчивает своё исполнение. Для создания локальной
статической переменной необходимо использовать ключевое слово static.


#include<iostream>
using namespace std;

void SomeFunc() {
	static int a = 0;
	a++;
	cout << a << endl;
}

int main() {
	SomeFunc();
	SomeFunc();
	SomeFunc();

	return 0;
}

Статические переменные в C++ имеют ряд особенностей и поведения в памяти, которые важно понимать:

Определение:
Статическая переменная - это переменная, которая сохраняет свое значение между вызовами функции и областью видимости, в которой она определена. Она существует в течение всего времени выполнения программы и инициализируется только один раз при первом запуске программы.

Область видимости:
Статическая переменная доступна только в том блоке, функции или файле, в котором она определена. Она не может быть использована за пределами своей области видимости.

Хранение в памяти:
Статические переменные хранятся в специальном сегменте памяти, называемом статической памятью или сегментом данных. Этот сегмент выделяется в момент запуска программы и освобождается при завершении работы программы. Поэтому статические переменные сохраняют свое значение даже после выхода из области видимости.

Инициализация:
Статическая переменная инициализируется только один раз, перед тем как программа начнет выполняться. Если значение не указано явно при инициализации, статическая переменная получит значение по умолчанию для своего типа данных.

Длительность жизни:
Статические переменные существуют на протяжении всего времени выполнения программы и их длительность жизни ограничена временем выполнения программы.

Модификатор static:
Ключевое слово static также может использоваться для определения статических переменных внутри функций и методов классов. В этом случае переменная существует в течение всего времени выполнения программы, но доступ к ней ограничен областью видимости функции или метода.

Потокобезопасность:
Статические переменные могут привести к проблемам с потокобезопасностью в многопоточных приложениях. Если необходимо использовать статическую переменную в многопоточной среде, ее доступ должен быть защищен с помощью механизмов синхронизации, таких как мьютексы или атомарные операции.

Использование статических переменных может быть полезным для сохранения состояния между вызовами функций, организации счетчиков, кеширования данных и других задач, где требуется сохранение значения переменной между вызовами функций. Однако их использование должно быть ограничено только теми случаями, где это действительно необходимо, чтобы избежать проблем с поддержкой и пониманием кода.

inline


inline в C++ - это способ компилятора уменьшить время выполнения программы, копируя код функции туда, где она вызывается, вместо того, чтобы создавать отдельный вызов функции.

Inline функция избавляет процессор прыгать в ячейку, по адресу которой начинается эта функция. Сам смысл inline состоит в том, чтобы вместо вызова функции подставить ее тело (код функции) в место, где она вызывается.

Когда мы пишем функцию и помечаем ее как inline, мы говорим компилятору, что хотим, чтобы он скопировал код этой функции в каждое место, где мы ее вызываем, вместо того, чтобы создавать отдельный вызов функции. Это помогает сделать нашу программу быстрее, потому что вызовы функций могут быть медленными из-за накладных расходов времени на передачу аргументов и возврат из функции.

Кроме того, использование inline может сделать наш код более компактным и улучшить его читаемость, потому что код функции будет виден прямо в том месте, где он вызывается.

Однако inline - это не всегда хорошая идея. Если функция очень большая или вызывается очень часто, компилятор может решить не копировать ее код в каждое место вызова, чтобы сэкономить место в памяти. Также, если мы используем inline в большом количестве функций, это может привести к увеличению размера исполняемого файла.


inline в C++ говорит компилятору следующее: "Вставь код функции прямо туда, где мы ее вызываем, вместо того, чтобы создавать отдельный вызов функции". Это помогает сделать программу быстрее, потому что вызовы функций могут занимать много времени.

Преимущества inline:

Ускорение программы за счет сокращения времени на вызовы функций.
Более компактный код и лучшая читаемость.
Недостатки inline:

Вставка кода функций может увеличить размер программы.
Не все функции подходят для inline, особенно если они очень большие или вызываются очень часто.
В целом, inline - это способ сделать программу быстрее, но его следует использовать осторожно, чтобы избежать нежелательных побочных эффектов.


Код:

#include <iostream>

// Определение инлайн функции для вычисления суммы двух чисел
inline int sum(int a, int b) {
    return a + b;
}

int main() {
    int num1 = 5;
    int num2 = 7;
    
    // Вызов инлайн функции sum() для вычисления суммы двух чисел
    int result = sum(num1, num2);
    
    // Вывод результата на экран
    std::cout << "Сумма чисел " << num1 << " и " << num2 << " равна: " << result << std::endl;
    
    return 0;
}

Если мерить философски – количество кода с inline функцией увеличилось. Вместо одной строки вызова функции ее тело, подставленное вместо вызова , дало целых 6 строк. Так же будет и в скомпилированной программе – количество операторов возрастет многократно – на столько, сколько операторов в теле функции и сколько раз ее вписали в программу.

Т.е. различие между inline функцией и обычной функцией – дублирование кода тела функции везде, где она оказывается задействована. В обычной функции, её тело находится в единственном экземпляре в одном и том же месте внутри программы.

Где здесь выгода спросите вы? Экономится время процессора на прыжки с места вызова в тело функции. Если функция огромная и используется в нескольких местах, то inline получается не совсем выгодно. Однако, если функция (тело её) маленькое, с минимальным количеством операторов, решающих задачу, в старину было удобнее отказаться от прыжка и просто подставить их в нужное место, как будто сам программист там их описал.

Как бы там ни было, в бытовых условиях да еще и на современных компьютерах, программы, использующие inline подстановку тела функции вместо вызова, не дают особых преимуществ. Поэтому использовать этот вид функции приходится достаточно редко. ИМХО, ему место в музее славы. Хотя, чтоб быть до конца честным, такой подход дает свои плоды тем, кто программирует контроллеры, процессоры и прочие железяки. Но там свои особенности и свой подход, и в это углубляться сейчас не стоит. Использовать встроенную функцию (inline функцию) или нет – решать самому программисту. От себя могу добавить только одно – не стоит делать это там, где этого не требуется по заданию.

Первоначальное назначение ключевого слова inline состояло в том, чтобы служить индикатором для оптимизатора, что встроенная подстановка функции предпочтительнее вызова функции, то есть вместо выполнения команды CPU для передачи управления в тело функции, копия тела функции выполняется без генерирования вызова. Эта оптимизация (inline expansion) основана на идее, что выполнение вызова функции является относительно дорогостоящим: оно требует перехода к новой подпрограмме, передачи аргументов функции и копирования возвращаемых значений. Inline expansion подавляет вызов функции путем копирования инструкций функции непосредственно в тело вызывающего объекта.
Последствия такой оптимизации в программе может быть очень трудно предвидеть. В дополнение к уменьшению накладных расходов на вызов функций, inline expansion позволяет выполнять широкий спектр дополнительных оптимизаций, которые в противном случае было бы очень трудно выполнить между вызовами функций. Однако не забывайте, что inline expansion создает копию тела функции для каждого вызова. Как следствие, помимо очевидного увеличения размера программы, дублирование инструкций делает программу кэш-недружественной.
Inline expansion может значительно повысить производительность, но это не точно. Производительность должна измеряться, а не предполагаться.
Т.к. программисты редко могут хорошо управлять оптимизациями, с них эта обязанность была снята, и современные компиляторы сами решают, когда применить inline expansion, а когда - не нужно.

Перегрузка функций - это возможность определения нескольких функций с одинаковым именем, но различными параметрами. Когда функция вызывается с определенными аргументами, компилятор определяет, какая именно функция должна быть вызвана на основе типов и количества переданных аргументов.


Когда компилятор обрабатывает перегруженные функции, он генерирует различные сигнатуры для каждой функции на основе их имен и типов параметров. Эти сигнатуры используются для различения функций во время компиляции и создания объектного файла.

После компиляции, когда программа загружается в память для выполнения, различные версии перегруженных функций хранятся в соответствующих сегментах памяти. Все функции с одинаковым именем, но с различными сигнатурами, могут быть хранятся вместе или в разных сегментах памяти в зависимости от реализации компилятора и среды выполнения.

Когда вызывается перегруженная функция, среда выполнения использует сигнатуры функций, чтобы определить, какую именно функцию нужно вызвать на основе переданных аргументов. Затем соответствующая функция загружается из памяти и выполняется.

Таким образом, перегрузка функций влияет на использование памяти программой во время выполнения, так как различные версии функций должны храниться в памяти для последующего вызова. Однако, эти дополнительные расходы памяти обычно минимальны по сравнению с общим объемом программы, и перегрузка функций позволяет создавать более гибкий и удобный код.


#include<iostream>
using namespace std;

int sum(int a, int b) {
	return a + b;
}

// Перегрузка функции для вычисления суммы трех чисел
int sum(int a, int b, int c) {
	return a + b + c;
}

int main() {

	int result1 = sum(5, 3); // Вызов первой перегруженной функции
	int result2 = sum(4, 7, 2); // Вызов второй перегруженной функции

	std::cout << "Result 1: " << result1 << std::endl;
	std::cout << "Result 2: " << result2 << std::endl;

	return 0;
}

Когда компилируется программа с перегруженными функциями, компилятор создает для каждой версии функции уникальный идентификатор или сигнатуру, основанную на именах функций и типах их параметров. Эти сигнатуры помогают компилятору и линкеру отличать различные версии функций друг от друга.

В момент выполнения программы, когда функция вызывается с определенными аргументами, среда выполнения использует сигнатуры функций для определения, какую именно версию функции нужно вызвать. Затем среда выполнения находит соответствующий адрес в памяти, где находится код этой функции, и передает управление этой версии функции.

Когда программа использует перегруженные функции, каждая версия функции занимает некоторое место в памяти. Однако объем занимаемой памяти зависит от многих факторов, включая оптимизации компилятора, особенности архитектуры процессора и т. д. В большинстве случаев перегрузка функций не приводит к значительному увеличению потребляемой памяти.

Кроме того, некоторые среды выполнения и компиляторы могут использовать различные методы оптимизации, такие как таблицы виртуальных функций или таблицы имен, для уменьшения накладных расходов при вызове перегруженных функций.

Таким образом, перегрузка функций может влиять на использование памяти программой, но эти накладные расходы обычно являются незначительными по сравнению с преимуществами, которые она приносит в виде гибкости и удобства в написании кода.

Шаблоны функций - это способ создания универсальных функций, которые могут работать с различными типами данных без необходимости явного указания типа данных в определении функции. Они позволяют писать код, который может быть использован с различными типами данных, делая его более гибким и переиспользуемым.

#include <iostream>

// Объявление шаблона функции
template <typename T>
T maximum(T x, T y) {
    if (x > y) {
        return x;
    } else {
        return y;
    }
}

int main() {
    int intResult = maximum(5, 3); // Вызов шаблона функции с целыми числами
    double doubleResult = maximum(4.5, 2.3); // Вызов шаблона функции с числами с плавающей запятой
    
    std::cout << "Максимальное целое число: " << intResult << std::endl;
    std::cout << "Максимальное число с плавающей запятой: " << doubleResult << std::endl;
    
    return 0;
}

 шаблонные функции также работают в памяти, как и обычные функции. Однако, процесс работы с шаблонными функциями немного отличается.

Во время компиляции, компилятор использует шаблонную функцию для создания конкретных экземпляров функций для каждого типа данных, с которым она используется в коде. Эти конкретные экземпляры функций затем компилируются в объектный код вместе с остальной программой.

Когда программа запускается, все созданные экземпляры шаблонных функций хранятся в памяти, как и обычные функции. Каждый экземпляр функции занимает свое место в памяти, и к нему можно обратиться при вызове функции с соответствующим типом данных.

Таким образом, шаблонные функции не отличаются от обычных функций в том, как они работают в памяти. Они создаются во время компиляции и доступны во время выполнения программы так же, как и любые другие функции.

 Давайте рассмотрим пример шаблона функции, который принимает несколько типов данных в качестве параметров и возвращает их сумму

#include <iostream>

// Шаблон функции для вычисления суммы нескольких значений разных типов
template <typename T1, typename T2>
auto sum(T1 a, T2 b) {
    return a + b;
}

int main() {
    int a = 5;
    double b = 3.7;

    auto result = sum(a, b);

    std::cout << "Сумма чисел: " << result << std::endl;

    return 0;
}


В этом примере шаблонная функция sum принимает два аргумента разных типов данных T1 и T2, а затем возвращает их сумму. Мы использовали ключевое слово auto для определения типа результата функции, который будет автоматически выведен компилятором на основе переданных аргументов.

Этот пример иллюстрирует использование шаблонных функций с несколькими параметрами для работы с разными типами данных в рамках одной функции.

Лямбда-функции - это специальный вид функций в C++, который позволяет создавать анонимные функции на месте, без явного объявления функции с именем. Они часто используются для написания небольших кусков кода, которые передаются в качестве аргументов другим функциям, таким как алгоритмы стандартной библиотеки или функции высшего порядка.

#include <iostream>

int main() {
    // Пример лямбда-функции, которая выводит переданное значение
    auto printValue = [](int value) {
        std::cout << "Значение: " << value << std::endl;
    };

    // Вызов лямбда-функции
    printValue(10);

    return 0;
}

В этом примере мы создаем лямбда-функцию, которая принимает один аргумент типа int и выводит его значение на экран. Мы используем ключевое слово auto, чтобы определить тип переменной printValue как тип лямбда-функции.

#include <iostream>

int main() {
    // Лямбда-функция для вычисления квадрата числа
    auto square = [](int x) {
        return x * x;
    };

    // Вызов лямбда-функции
    int number = 5;
    int result = square(number);
    std::cout << "Квадрат числа " << number << ": " << result << std::endl;

    return 0;
}
