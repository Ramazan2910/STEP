• Статический полиморфизм:

• Он достигается с помощью перегрузки функций и операторов, а также с использованием шаблонов.

• Решение, какая функция или оператор будет вызвана, принимается на этапе компиляции.

• Примеры:

• Перегрузка функций, когда разные функции с одним и тем же именем, но разными параметрами, вызываются в зависимости от контекста.

• Шаблоны функций и классов, позволяющие создавать обобщенные алгоритмы, которые могут работать с разными типами данных.


// Пример статического полиморфизма через перегрузку функций:
int add(int a, int b) {
    return a + b;
}

double add(double a, double b) {
    return a + b;
}



• Динамический полиморфизм:

• Он достигается с использованием виртуальных функций и наследования.

• Решение, какая функция будет вызвана, принимается во время выполнения программы, в зависимости от типа объекта.

• Примеры:

• Виртуальные функции позволяют создавать базовые классы с общими методами, которые могут быть переопределены в производных классах.

• Позднее связывание (late binding), когда вызываемая функция определяется во время выполнения программы.




// Пример динамического полиморфизма через виртуальные функции:
class Shape {
public:
    virtual void draw() {
        cout << "Drawing a shape" << endl;
    }
};

class Circle : public Shape {
public:
    void draw() override {
        cout << "Drawing a circle" << endl;
    }
};

class Square : public Shape {
public:
    void draw() override {
        cout << "Drawing a square" << endl;
    }
};

int main() {
    Shape *shape1 = new Circle();
    Shape *shape2 = new Square();
    
    shape1->draw(); // Выведет: "Drawing a circle"
    shape2->draw(); // Выведет: "Drawing a square"
    
    delete shape1;
    delete shape2;
    return 0;
}



Здесь метод draw() в классе Shape объявлен виртуальным, и его реализации в классах-наследниках Circle и Square переопределены. Когда вызывается метод draw() для объектов shape1 и shape2, определяется их реальный тип и вызывается соответствующая реализация метода.

На уровне памяти динамический полиморфизм в C++ обычно реализуется с использованием виртуальных функций и таблиц виртуальных функций (таблиц виртуальных методов, VTBL).

Рассмотрим, как это работает:

Виртуальные функции:
Виртуальная функция - это функция, которая может быть переопределена в производных классах и вызвана через указатель или ссылку на базовый класс.
Каждый объект класса содержит указатель на таблицу виртуальных функций (VTBL), если в классе есть хотя бы одна виртуальная функция. Этот указатель называется указателем на VTBL или указателем на виртуальные функции.
Таблица виртуальных функций (VTBL):
Каждый класс с виртуальными функциями имеет свою собственную таблицу виртуальных функций, содержащую адреса виртуальных функций этого класса.
Все объекты этого класса используют одну и ту же таблицу виртуальных функций.
Эта таблица располагается в памяти при компиляции программы и доступна через указатель на VTBL в объекте.
Динамический выбор функции:
Когда вызывается виртуальная функция через указатель или ссылку на базовый класс, компилятор не знает точный тип объекта в момент компиляции.
Вместо этого он использует таблицу виртуальных функций, на которую указывает указатель в объекте, чтобы определить, какую функцию вызвать.
Таким образом, на этапе выполнения программы используется таблица виртуальных функций для определения функции, которую нужно вызвать.

#include <iostream>

class Shape {
public:
    virtual void draw() {
        std::cout << "Drawing Shape" << std::endl;
    }
};

class Circle : public Shape {
public:
    void draw() override {
        std::cout << "Drawing Circle" << std::endl;
    }
};

int main() {
    Circle circle;
    Shape* shapePtr = &circle; // Указатель на базовый класс, указывающий на объект производного класса

    shapePtr->draw(); // Вызов виртуальной функции

    return 0;
}


В этом примере:

Создается объект circle типа Circle.
Указатель shapePtr на базовый класс Shape присваивается адресу объекта circle.
Когда вызывается shapePtr->draw(), компилятор использует таблицу виртуальных функций для определения, какую функцию вызвать. Так как объект circle является типа Circle, то и вызывается функция draw() из класса Circle.


На уровне памяти это выглядит приблизительно следующим образом:

lua


+---------------------+
|       Shape         |
|    vptr -> [0]------|---> VTBL Shape: [address of Shape::draw()]
+---------------------+
|       Circle        |
+---------------------+


Здесь vptr - указатель на таблицу виртуальных функций (VTBL). Указатель на VTBL объекта Circle указывает на VTBL класса Circle, который содержит адрес функции Circle::draw(). Когда вызывается виртуальная функция через указатель на базовый класс, компилятор использует vptr для доступа к соответствующей таблице виртуальных функций и выбора правильной функции для вызова.

Рассмотрим другой пример, где у нас есть базовый класс Animal и производные классы Dog и Cat, и каждый из них переопределяет виртуальную функцию makeSound():

#include <iostream>

// Базовый класс Animal
class Animal {
public:
    // Виртуальная функция makeSound
    virtual void makeSound() {
        std::cout << "Animal makes a sound" << std::endl;
    }
};

// Производный класс Dog
class Dog : public Animal {
public:
    // Переопределение виртуальной функции makeSound
    void makeSound() override {
        std::cout << "Dog barks" << std::endl;
    }
};

// Производный класс Cat
class Cat : public Animal {
public:
    // Переопределение виртуальной функции makeSound
    void makeSound() override {
        std::cout << "Cat meows" << std::endl;
    }
};

int main() {
    Animal* animalPtr;

    Dog dog;
    Cat cat;

    // Присваиваем указатель на объект класса Dog
    animalPtr = &dog;
    // Вызываем виртуальную функцию makeSound()
    animalPtr->makeSound(); // Выводит "Dog barks"

    // Присваиваем указатель на объект класса Cat
    animalPtr = &cat;
    // Вызываем виртуальную функцию makeSound()
    animalPtr->makeSound(); // Выводит "Cat meows"

    return 0;
}


На уровне памяти это можно представить следующим образом:

+-----------------------+
|         Animal        |
|       vptr -> [0]-----|--> VTBL Animal: [address of Animal::makeSound()]
+-----------------------+
|          Dog          |
+-----------------------+
|          Cat          |
+-----------------------+


Когда мы вызываем animalPtr->makeSound(), компилятор использует указатель vptr, чтобы найти соответствующую таблицу виртуальных функций (VTBL) и вызвать правильную версию makeSound() в зависимости от типа объекта (Dog или Cat).


Давайте поподробнее разберем, как работает динамический полиморфизм на уровне памяти.

Компиляция и VTBL:При компиляции для каждого класса с виртуальными функциями создается таблица виртуальных функций (VTBL). В этой таблице содержатся адреса всех виртуальных функций, определенных в этом классе.Рассмотрим пример с классами Animal, Dog и Cat. При компиляции для этих классов будут созданы соответствующие VTBL:

VTBL Animal: [address of Animal::makeSound()]
VTBL Dog:    [address of Dog::makeSound()]
VTBL Cat:    [address of Cat::makeSound()]


Объекты и указатели:При создании объекта класса, например, Dog dog;, помимо данных объекта в памяти также выделяется место для указателя на VTBL (назовем его vptr). Этот указатель указывает на VTBL соответствующего класса.

+-------------------------+
|           Dog           |
|        vptr -> [0]------|--> VTBL Dog:    [address of Dog::makeSound()]
+-------------------------+


Когда создается указатель на базовый класс, он может указывать на объекты как базового класса, так и его производных классов:

Animal* animalPtr;
Dog dog;
Cat cat;
animalPtr = &dog;
animalPtr = &cat;

Вызов виртуальной функции:Когда вызывается виртуальная функция через указатель на базовый класс, компилятор использует vptr для доступа к соответствующей VTBL и выбора нужной функции.Например, при вызове animalPtr->makeSound() компилятор:
Переходит к vptr и получает адрес VTBL объекта, на который указывает animalPtr.
Использует этот адрес для доступа к соответствующей VTBL.
Получает адрес функции makeSound() из VTBL.
Вызывает функцию по этому адресу.
Таким образом, даже если animalPtr указывает на объект класса Dog, будет вызвана правильная функция Dog::makeSound(), потому что компилятор на этапе выполнения программы определяет, какую версию функции использовать, используя vptr.
Таким образом, динамический полиморфизм в C++ позволяет вызывать функции через указатель или ссылку на базовый класс, а конкретная функция вызывается в зависимости от типа объекта в момент выполнения программы, что делает код более гибким и удобным для работы с иерархиями классов.

Виртуальные методы в C++ позволяют реализовывать полиморфизм, что позволяет использовать один и тот же метод для объектов разных классов в иерархии наследования. Рассмотрим более подробно, как они работают.

Определение виртуальных методов:Виртуальные методы объявляются в базовом классе с ключевым словом virtual:

class Base {
public:
    virtual void someFunction() {
        // Реализация
    }
};


Ключевое слово virtual указывает, что этот метод является виртуальным, и его можно будет переопределить в производных классах.
Переопределение виртуальных методов:В производных классах методы, объявленные как виртуальные в базовом классе, могут быть переопределены с помощью ключевого слова override:

class Derived : public Base {
public:
    void someFunction() override {
        // Переопределенная реализация
    }
};

Ключевое слово override указывает компилятору, что метод должен переопределить виртуальный метод базового класса. Если метод в производном классе не соответствует ни одному виртуальному методу базового класса, будет ошибка компиляции.
Вызов виртуальных методов:Виртуальные методы вызываются через указатель или ссылку на базовый класс. Компилятор во время выполнения программы определяет, какой метод вызывать, в зависимости от типа объекта, на который указывает указатель или ссылка:

Base* ptr = new Derived();
ptr->someFunction(); // Вызывается метод Derived::someFunction(), если он переопределен

В данном примере, если метод someFunction() был переопределен в классе Derived, то будет вызвана именно его версия, а не версия из базового класса.
Позднее связывание (Late Binding):Выбор правильной версии метода происходит на этапе выполнения программы, что называется поздним связыванием. Это позволяет динамически определять, какой метод вызывать в зависимости от типа объекта.Например, если у вас есть массив указателей на объекты базового класса, которые могут указывать на объекты производных классов, то при вызове метода через такие указатели будет вызвана правильная версия метода для каждого объекта.
Виртуальный деструктор:Важно помнить, что если у вас есть виртуальные методы в классе, который вы используете в качестве базового, то вам также нужен виртуальный деструктор. Это гарантирует корректное освобождение памяти при удалении объектов через указатель на базовый класс.

class Base {
public:
    virtual ~Base() {} // Виртуальный деструктор
};


Если деструктор не объявлен виртуальным, при удалении объекта через указатель на базовый класс могут возникнуть утечки памяти.
Использование виртуальных методов позволяет создавать гибкие и удобные иерархии классов, что делает код более поддерживаемым и расширяемым.

Виртуальный деструктор - это деструктор в базовом классе, который объявлен как виртуальный. Обычно он используется в иерархиях классов, где есть полиморфизм.

Вот как он выглядит:

class Base {
public:
    virtual ~Base() {
        // код деструктора
    }
};


Ключевое слово virtual перед деструктором ~Base() делает его виртуальным. Это гарантирует, что если вы удаляете объект производного класса через указатель на базовый класс, то будет вызван правильный деструктор для объекта производного класса.

Почему виртуальные деструкторы важны?

В иерархии классов, если у вас есть виртуальные функции, вы обычно должны иметь виртуальный деструктор. Это связано с тем, что при удалении объекта производного класса через указатель на базовый класс компилятор должен знать, какой деструктор вызывать.

Проблема без виртуальных деструкторов:

Рассмотрим следующий пример:

class Base {
public:
    ~Base() {
        std::cout << "Base destructor called" << std::endl;
    }
};

class Derived : public Base {
public:
    ~Derived() {
        std::cout << "Derived destructor called" << std::endl;
    }
};

int main() {
    Base* ptr = new Derived();
    delete ptr; // вызывается только деструктор Base
    return 0;
}


Здесь при удалении объекта ptr, который указывает на объект класса Derived, будет вызван только деструктор Base, а деструктор Derived не будет вызван. Это может привести к утечкам ресурсов или неправильному освобождению памяти.

Решение с виртуальным деструктором:

Если виртуальный деструктор объявлен в базовом классе, даже если объект удаляется через указатель на базовый класс, вызывается деструктор правильного типа:

class Base {
public:
    virtual ~Base() {
        std::cout << "Base destructor called" << std::endl;
    }
};

class Derived : public Base {
public:
    ~Derived() {
        std::cout << "Derived destructor called" << std::endl;
    }
};

int main() {
    Base* ptr = new Derived();
    delete ptr; // вызывается деструктор Derived, а затем Base
    return 0;
}


Теперь при удалении объекта ptr сначала вызывается деструктор Derived, а затем Base, что гарантирует корректное освобождение всех ресурсов, выделенных для объекта Derived.
