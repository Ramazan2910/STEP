# Методы синхронизации потоков в C#

## Введение
Когда несколько потоков работают с одними и теми же ресурсами (например, с общей памятью или данными), может возникнуть проблема состояния гонки (race conditions), когда несколько потоков одновременно пытаются изменить одни и те же данные, что может привести к ошибкам. Для решения этой проблемы используются механизмы синхронизации.
#

Синхронизация потоков в C# необходима для предотвращения гонки данных, обеспечения корректного доступа к разделяемым ресурсам и управления потоками в многопоточных приложениях. В .NET предусмотрено несколько механизмов синхронизации потоков, каждый из которых подходит для определённых сценариев.

## Основные методы синхронизации

### 1. `lock`
Простая и удобная конструкция для синхронизации доступа к объектам.

```csharp
private static readonly object _lockObject = new();

public void CriticalSection()
{
    lock (_lockObject)
    {
        // Код, выполняемый только одним потоком в данный момент
    }
}
```

**Плюсы:**
- Простота использования
- Оптимизирован для большинства сценариев

**Минусы:**
- Подходит только для блокировки одного ресурса
- Может привести к взаимоблокировкам (deadlocks)

---

### 2. `Monitor`
Позволяет более гибко управлять блокировкой, чем `lock`.

```csharp
private static readonly object _monitorLock = new();

public void CriticalSection()
{
    try
    {
        Monitor.Enter(_monitorLock);
        // Код критической секции
    }
    finally
    {
        Monitor.Exit(_monitorLock);
    }
}
```

**Плюсы:**
- Позволяет использовать `Wait`, `Pulse`, `PulseAll` для управления потоками

**Минусы:**
- Требует явного вызова `Monitor.Exit()`
- Может привести к блокировке потока при неправильном использовании

---

### 3. `Mutex`
`Mutex` (Mutual Exclusion) — это механизм межпоточной и межпроцессной синхронизации, использующий потоки операционной системы. В отличие от `lock` и `Monitor`, `Mutex` работает на уровне ядра ОС и может синхронизировать выполнение не только внутри одного процесса, но и между разными процессами.

```csharp
// First Example
private static readonly Mutex _mutex = new();

public void CriticalSection()
{
    _mutex.WaitOne(); // Запрос блокировки
    try
    {
        // Код критической секции
    }
    finally
    {
        _mutex.ReleaseMutex(); // Освобождение блокировки
    }
}

// Second Example

class Program
{
    private static Mutex mutex = new();
    
    public static void CountToFive()
    {
        mutex.WaitOne();

        for (int i = 0; i < 5; i++)
        {
            Console.WriteLine($"This is {i} from thread: {Thread.CurrentThread.ManagedThreadId}");
        }
        mutex.ReleaseMutex();
    }

    public static void Main(string[] args)
    {
        Console.WriteLine("Main started...");
        for (int i = 0; i < 5; i++)
        {
            Thread th = new(CountToFive);
            Console.WriteLine($"Created thread");
            //Даже если ты запускаешь поток, ОС не гарантирует, что поток начнёт выполнение немедленно. Часто ОС ставит его в очередь на выполнение, а пока поток стартует — главный поток уже успел вывести остальные "Created thread".
            th.Start();
        }
    }
}
```

**Плюсы:**
- Поддерживает межпроцессную синхронизацию
- Может использоваться для защиты разделяемых ресурсов между разными приложениями

**Минусы:**
- `Mutex` тяжелее, чем `lock` и `Monitor`, так как задействует потоки системы (kernel-mode synchronization)
- Производительность ниже, чем у `lock`, из-за необходимости взаимодействия с ядром ОС
- Может привести к дедлокам при неправильном использовании

---

### 4. `Semaphore` и `SemaphoreSlim`
Ограничивает количество потоков, одновременно выполняющих код.

#### `Semaphore`
`Semaphore` — это механизм синхронизации, который позволяет ограничить количество потоков, имеющих доступ к ресурсу. Он поддерживает межпроцессную синхронизацию, так как работает на уровне ядра операционной системы. Если нам не обезательно работать с одними данными вместе просто использовать для увеличения скорости выполнения.

```csharp
private static readonly Semaphore _semaphore = new(2, 2);

public void CriticalSection()
{
    _semaphore.WaitOne();
    try
    {
        // Код критической секции
    }
    finally
    {
        _semaphore.Release();
    }
}
```

**Плюсы:**
- Позволяет контролировать число одновременно работающих потоков
- Поддерживает межпроцессную синхронизацию

**Минусы:**
- Медленнее `SemaphoreSlim`, так как использует системные объекты ядра

#### `SemaphoreSlim`
`SemaphoreSlim` — это облегчённая версия `Semaphore`, предназначенная только для внутрипроцессной синхронизации. Он более эффективен, так как не использует объекты ядра ОС.

```csharp
private static readonly SemaphoreSlim _semaphoreSlim = new(2, 2);

public async Task CriticalSectionAsync()
{
    await _semaphoreSlim.WaitAsync();
    try
    {
        // Код критической секции
    }
    finally
    {
        _semaphoreSlim.Release();
    }
}
```

**Плюсы:**
- Более производителен, чем `Semaphore`, так как работает без взаимодействия с ядром ОС
- Поддерживает асинхронные операции (`WaitAsync`)

**Минусы:**
- Не поддерживает межпроцессную синхронизацию

#### Различия между `Semaphore` и `SemaphoreSlim`
| Характеристика  | `Semaphore` | `SemaphoreSlim` |
|----------------|------------|---------------|
| Поддержка межпроцессной синхронизации | Да | Нет |
| Производительность | Медленнее (использует ядро ОС) | Быстрее (использует память процесса) |
| Поддержка асинхронности | Нет | Да (`WaitAsync`) |
| Использование в ASP.NET и UI-приложениях | Не рекомендуется | Рекомендуется |

### 5. `AutoResetEvent` и `ManualResetEvent`
События для управления выполнением потоков.

`ManualResetEvent` - то же самое что и countdownEvent просто ручной счетчик.
`ManualResetEvent` — это синхронизационный объект, который используется для управления потоками. Он позволяет одному потоку сигнализировать другим, чтобы они могли продолжить выполнение. Когда объект в **неактивном** состоянии (значение `false`), потоки, вызвавшие `WaitOne()`, блокируются. После вызова метода **`Set()`**, событие переходит в **активное** состояние (значение `true`), и все заблокированные потоки продолжают выполнение. Состояние события остаётся активным до вызова `Reset()`.

```csharp
using System;
using System.Threading;

class Program
{
    // [1] Создаём ManualResetEvent, который будет блокировать главный поток, пока все потоки не завершат свою работу
    private static readonly ManualResetEvent manualEvent = new(false);

    // [2] Переменная для отслеживания числа завершённых потоков
    private static int completedThreads = 0;

    // [3] Объект для синхронизации доступа к переменной completedThreads
    private static readonly object lockObject = new();

    // [4] Метод, выполняемый каждым потоком
    static void Worker(int id)
    {
        // [5] Выводим сообщение, что поток начал выполнение
        Console.WriteLine($"Поток {id} начал выполнение.");

        // [6] Имитация работы потока
        Thread.Sleep(100);

        // [7] Выводим сообщение, что поток завершил выполнение
        Console.WriteLine($"Поток {id} завершил выполнение.");

        // [8] Защищаем переменную completedThreads от одновременного изменения несколькими потоками
        lock (lockObject)
        {
            // [9] Увеличиваем счётчик завершённых потоков
            completedThreads++;

            // [10] Если все потоки завершили выполнение (3 потока), уведомляем главный поток
            if (completedThreads == 3)
            {
                manualEvent.Set(); // Устанавливаем состояние события в "сигнализировать", чтобы разблокировать Main поток
            }
        }
    }

    // [11] Главный метод, где происходит запуск потоков и ожидание их завершения
    static void Main()
    {
        // [12] Выводим сообщение о запуске потоков
        Console.WriteLine("Запуск потоков...");

        // [13] Запускаем 3 потока, каждый из которых выполняет метод Worker с уникальным id
        for (int i = 1; i <= 3; i++)
        {
            new Thread(() => Worker(i)).Start();
        }

        // [14] Выводим сообщение, что Main поток ожидает завершения всех потоков
        Console.WriteLine("Ожидание завершения всех потоков...");

        // [15] Главный поток блокируется до тех пор, пока все потоки не завершат выполнение
        manualEvent.WaitOne(); // Ожидаем, пока метод Set() не будет вызван

        // [16] Когда все потоки завершены, выводим сообщение, что Main продолжает выполнение
        Console.WriteLine("Все потоки завершены, продолжаем выполнение Main.");
    }
}
```

`AutoResetEvent` — это синхронизационный примитив в C#, который используется для управления потоками, похожий на ManualResetEvent, но с ключевым отличием: он автоматически сбрасывает своё состояние в неактивное после того, как один поток был разблокирован.

Как работает `AutoResetEvent`:
Неактивное состояние (false):
- Если объект находится в неактивном состоянии, потоки, вызывающие WaitOne(), будут заблокированы.

Активное состояние (true):
1. Когда вызывается метод Set(), объект переключается в активное состояние и разблокирует один поток, который вызвал WaitOne().
2. После того как поток продолжит выполнение, объект автоматически сбрасывает своё состояние обратно в неактивное, даже без вызова Reset().``

## Заключение
Выбор метода синхронизации зависит от требований к производительности, сложности кода и особенностей взаимодействия потоков.
- `lock` и `Monitor` подходят для большинства случаев
- `Mutex` полезен при межпроцессной синхронизации, но медленнее `lock`
- `Semaphore` ограничивает количество активных потоков, поддерживает межпроцессную синхронизацию, но медленный
- `SemaphoreSlim` эффективен в рамках одного процесса и поддерживает `async/await`
- `AutoResetEvent` и `ManualResetEvent` позволяют управлять последовательностью выполнения
- `Concurrent` коллекции обеспечивают потокобезопасность без явной блокировки

При использовании многопоточности важно учитывать возможность взаимоблокировок, задержек и накладных расходов при синхронизации потоков.


### 6.countdownEvent

CountdownEvent — это специальный класс из пространства имён System.Threading, который используется для сигналирования группы потоков. `ОН НЕ ИМЕЕТ ОТНОШЕНИЕ К СИНХРОНИЗАЦИИ!!!!`

```csharp
using System;
using System.Threading;

class Program
{
    // [1] Создаём объект CountdownEvent, который ждёт 5 сигналов
    private static CountdownEvent countdownEvent = new(5);

    // [2] Создаём мьютекс, чтобы синхронизировать доступ к консоли
    private static Mutex mutex = new();

    // [3] Метод, который будет выполняться в каждом потоке
    public static void Sample()
    {
        // [4] Захватываем мьютекс — только один поток может попасть внутрь за раз
        mutex.WaitOne();

        // [5] Печатаем 5 строк, чтобы показать работу потока
        for (int i = 0; i < 5; i++)
        {
            // [6] Показываем ID потока, который сейчас выполняется
            Console.WriteLine($"Hello from: {Thread.CurrentThread.ManagedThreadId}");
        }

        // [7] Сообщаем CountdownEvent, что один поток закончил работу
        countdownEvent.Signal();

        // [8] Освобождаем мьютекс — даём другим потокам зайти в критическую секцию
        mutex.ReleaseMutex();
    }

    // [9] Главный метод — точка входа
    public static void Main(string[] args)
    {
        // [10] Печатаем, что главный поток начался
        Console.WriteLine("Main started");

        // [11] Создаём и запускаем 5 потоков
        for (int i = 0; i < 5; i++)
        {
            // [12] Создаём поток, который выполняет метод Sample
            Thread th1 = new(Sample);

            // [13] Запускаем поток
            th1.Start();
        }

        // [14] Ждём, пока все 5 потоков вызовут Signal()
        countdownEvent.Wait();

        // [15] После завершения всех потоков выводим сообщение
        Console.WriteLine("Main finished");
    }
}
```
Ключевые моменты:

Счётчик: Устанавливаешь начальное значение счётчика, например, 5.

Signal(): Каждый поток вызывает Signal(), чтобы уменьшить счётчик на 1, когда завершает свою работу.

Wait(): Главный поток (или другой поток) вызывает Wait(), чтобы блокировать выполнение, пока счётчик не станет равен 0 (то есть, пока все потоки не закончат работу).
