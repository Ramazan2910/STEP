# Процессы

**_ Процесс - это экземпляр выполняемой программы. _**
Процесс состоит из виртуального адресного пространства, кода, данных и других ресурсов.
Процессы создаются и уничтожаются операционной системой.
Процессы выполняются параллельно и независимо друг от друга.

Наша операционная система независимо от ее типа и версии в любом
запускает какой-то запускаемый файл(.exec, .exe, .com и т.д.) в виде процесса.

Сам процесс может создавать другие процессы, которые называются дочерними процессами.

К примеру когда вы запускаете браузер, создается главный процесс и каждая вкладка -
это дочерний процесс.

Каждый процесс состоит из одного и более потоков.

**_Поток - это логическое обещание выполнения какой-либо задачи._**

## Функции манипулирования процессами

В .NET Core для манипулирования процессами используется
класс Process из пространства имен System.Diagnostics.

- Start() - запускает процесс.
- Kill() - завершает процесс.
- WaitForExit() - ожидает завершения процесса.

В старт вы можете передать путь к файлу, который хотите запустить,
а также аргументы командной строки.

Самое главное, что в классе процесс можно вызвать метод .GetExecutingAssembly()
и у него вызвать свойство .Threads и получить все потоки, которые
созданы в процессе.

Конечно, давай разберём этот код пошагово и подробно! Этот код запускает дочерний процесс в C#, использует событийную модель для получения данных из этого процесса и ожидает его завершения.

### Код:

```csharp
using System.Diagnostics;

Console.WriteLine($"Process with id: {Process.GetCurrentProcess().Id} started");

string childApp =
    "/Users/wayne/Documents/Work/FSDA_1_24_2_RU/Processes/ChildApp/bin/Debug/net9.0/ChildApp"; // Путь к исполняемому файлу

ProcessStartInfo psi = new ProcessStartInfo
{
    FileName = childApp,
    Arguments = "Elvin Ilkin Ramazan",
    RedirectStandardOutput = true
};

using Process process = new Process { StartInfo = psi };

process.EnableRaisingEvents = true;
process.OutputDataReceived += (sender, e) => Console.WriteLine(e.Data);
process.Exited += (sender, e) => Console.WriteLine($"Child process with id: {process.Id} finished");

process.Start();

Console.WriteLine($"Child process with id: {process.Id} started");

process.BeginOutputReadLine();

process.WaitForExit();

Console.WriteLine($"Process with id: {Process.GetCurrentProcess().Id} finished");
```

---

### 1. **Используемые пространства имён**:
```csharp
using System.Diagnostics;
```
Этот код использует пространство имён `System.Diagnostics`, которое предоставляет классы для работы с процессами, журналированием и отладкой. В частности, мы используем его для работы с процессами и получения данных о выполнении процессов.

---

### 2. **Вывод информации о текущем процессе**:
```csharp
Console.WriteLine($"Process with id: {Process.GetCurrentProcess().Id} started");
```
- **`Process.GetCurrentProcess().Id`**: Получаем **ID текущего процесса** (это процесс, в котором выполняется этот код).
- **`Console.WriteLine(...)`**: Выводим в консоль сообщение о том, что текущий процесс был запущен. Это будет полезно для отслеживания, какой процесс выполняет программу.

---

### 3. **Указание пути к дочернему приложению**:
```csharp
string childApp =
    "/Users/wayne/Documents/Work/FSDA_1_24_2_RU/Processes/ChildApp/bin/Debug/net9.0/ChildApp"; // Путь к исполняемому файлу
```
- В этой строке указывается **путь к исполняемому файлу дочернего приложения**, которое будет запущено.
- Путь задан как строка, это может быть любой файл, который можно запустить как процесс, например, приложение на C# или другой исполняемый файл.

---

### 4. **Настройка `ProcessStartInfo`**:
```csharp
ProcessStartInfo psi = new ProcessStartInfo
{
    FileName = childApp,
    Arguments = "Elvin Ilkin Ramazan",
    RedirectStandardOutput = true
};
```
- **`ProcessStartInfo`** — это объект, который используется для настройки параметров запуска процесса.
- **`FileName = childApp`**: Указываем путь к исполняемому файлу дочернего приложения (путь из предыдущего шага).
- **`Arguments = "Elvin Ilkin Ramazan"`**: Это **аргументы**, которые будут переданы дочернему приложению при запуске. В данном случае это строка, которая будет передана как один аргумент.
- **`RedirectStandardOutput = true`**: Указываем, что нужно **перехватывать стандартный вывод** дочернего процесса, чтобы вывод дочернего процесса можно было читать в нашем приложении.

---

### 5. **Создание и настройка процесса**:
```csharp
using Process process = new Process { StartInfo = psi };
```
- **`new Process { StartInfo = psi }`**: Создаём новый объект `Process` и настраиваем его с помощью ранее созданного `ProcessStartInfo` (psi). Это говорит процессу, что он должен использовать указанный путь к файлу и параметры для запуска.
- Используется конструкция `using`, чтобы процесс автоматически освободил ресурсы после завершения работы.

---

### 6. **Обработчик событий**:
```csharp
process.EnableRaisingEvents = true;
process.OutputDataReceived += (sender, e) => Console.WriteLine(e.Data);
process.Exited += (sender, e) => Console.WriteLine($"Child process with id: {process.Id} finished");
```
- **`process.EnableRaisingEvents = true`**: Включаем событие, которое будет срабатывать, когда процесс завершится.
- **`process.OutputDataReceived`**: Регистрируем обработчик для события, когда дочерний процесс отправляет данные на стандартный вывод (к примеру, через `Console.WriteLine` в дочернем приложении). Эти данные будут выводиться в консоль нашего приложения, используя `Console.WriteLine(e.Data)`.
- **`process.Exited`**: Регистрируем обработчик для события, которое срабатывает, когда дочерний процесс завершает своё выполнение. В этом обработчике выводим информацию о завершении дочернего процесса.

---

### 7. **Запуск дочернего процесса**:
```csharp
process.Start();
```
- **`process.Start()`**: Этот метод запускает дочерний процесс, используя настройки, заданные в `ProcessStartInfo` (путь и аргументы).

---

### 8. **Вывод информации о запуске дочернего процесса**:
```csharp
Console.WriteLine($"Child process with id: {process.Id} started");
```
- После того как дочерний процесс был запущен, выводим информацию о его **ID** в консоль.

---

### 9. **Чтение стандартного вывода дочернего процесса**:
```csharp
process.BeginOutputReadLine();
```
- **`process.BeginOutputReadLine()`**: Этот метод **начинает асинхронно читать** стандартный вывод дочернего процесса. Когда дочерний процесс будет что-то выводить, это будет перехвачено и передано в обработчик события `OutputDataReceived`.

---

### 10. **Ожидание завершения процесса**:
```csharp
process.WaitForExit();
```
- **`process.WaitForExit()`**: Этот метод заставляет основной процесс **ожидать завершения дочернего процесса**. Программа будет блокироваться, пока дочерний процесс не завершится.

---

### 11. **Вывод информации о завершении процесса**:
```csharp
Console.WriteLine($"Process with id: {Process.GetCurrentProcess().Id} finished");
```
- Когда дочерний процесс завершится, программа продолжит выполнение, и мы выводим информацию о завершении текущего процесса, в котором выполняется наш код.

---

## **Примечания**:

1. **Перехват вывода**:
   - Мы перехватываем стандартный вывод дочернего процесса через **`RedirectStandardOutput = true`** и **`process.BeginOutputReadLine()`**. Это позволяет нашему приложению обрабатывать вывод дочернего процесса без блокировки.

2. **Обработка завершения дочернего процесса**:
   - Мы используем событие **`process.Exited`**, чтобы получить уведомление о завершении процесса и выполнить действия, когда процесс завершится.

3. **Асинхронность**:
   - Чтение вывода происходит асинхронно с помощью `BeginOutputReadLine()`. Это позволяет не блокировать основной поток, а обработка данных происходит в фоновом потоке.
